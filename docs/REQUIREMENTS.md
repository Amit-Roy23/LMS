# Requirements Traceability Matrix & Client Specification

This document maps all client requirements (R1–R8) to the system architecture, implementation files, test suites, and status. It also records open decisions to be confirmed with the client.

## 2. Open Decisions (To Confirm with Client)

| # | Topic | Description & Options | Current Default / Fallback |
| :--- | :--- | :--- | :--- |
| **D1** | **Payment Gateway Integration** | Which Indian / International payment gateway is preferred? Options: Razorpay, PhonePe UPI, Cashfree, Stripe, or Manual UPI QR. | Abstract payment driver interface implemented; defaults to `MOCK` driver with pluggable `RAZORPAY` adapter stub. |
| **D2** | **Notification Dispatch Channel(s)** | Which channels should receive automated registration & payment confirmations? Options: WhatsApp Business API (Interakt / Gupshup / Twilio), Email (SendGrid / AWS SES / Resend), or SMS (Fast2SMS / Twilio). | Configurable notification driver with templates (`EMAIL`, `WHATSAPP`, `SMS`) and audit logging. |
| **D3** | **Quiz Pool Question Count** | Should quizzes draw a random subset of questions (e.g. 10 or 20 out of a 50-question bank) per attempt, or present all questions? | `Quiz.questionCount` field added (nullable = all questions; integer = random subset with shuffling). |
| **D4** | **Live Class Video Platform** | Which live streaming / conference provider should be integrated for LIVE batches? Options: Zoom SDK / OAuth, Google Meet API, YouTube Live private unlisted streams, or custom WebRTC. | `LiveProvider` enum (`ZOOM`, `MEET`, `YOUTUBE`, `OTHER`) with `joinUrl` and `recordingUrl` storage. |
| **D5** | **Official Certificate Diploma Layout** | Exact visual seal, signature images, issuer organization accreditation text, and dimensions for vector PDF generation. | High-resolution PDFKit engine with ED25519 hash validation and dynamic verification QR code pointing to `/verify/:certificateId`. |
| **D6** | **Live Batch Gating Policy** | For students in LIVE mode, should module/lesson access be strictly gated by live session calendar dates, or remain self-paced after class? | Configurable `timeGatedByLiveSession` setting in progression service. |
